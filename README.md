# tnt-fs

Файловая система фасадом поверх встроенного `fio`: всякий отказ — пара
`nil, err` с родом, кодом и текстом; ни одно действие не держит узел;
подмена файла, снос дерева и временный каталог с уборкой — готовые,
а не написанные руками в каждом пакете.

```lua
local fs = require('tnt.fs')

local text, err = fs.read('/etc/app/config.yaml')

if text == nil and err.kind == fs.MISSING then
    -- файла нет — это «так бывает», а не поломка
end

fs.replace('/var/lib/app/state.json', json.encode(state))  -- атомарно, со сбросом на диск
local wals = fs.glob('/var/lib/app/wal', '*.xlog')         -- без блокировки узла

fs.with_temp_dir(function(dir)
    -- черновик; каталог снесётся и при броске
end, { within = '/var/lib/app' })
```

Зависит от `tnt-must` (проверки аргументов) и `tnt-external` (подмена
`fio` в проверках).

## Зачем

`fio` делает работу, но три вещи оставляет вызывающему, и каждый пакет
дописывает их по-своему. Здесь они сделаны однажды:

- **Один вид отказа.** У `fio` их три: объект ошибки с `errno`, строка
  с причиной в конце и ложь с причиной в глобальном `errno()`, которую
  следующий вызов затирает. Здесь всякий отказ — таблица с родом
  (`missing`, `exists`, `denied`, `full`, `failed`), по которому можно
  решать, кодом и текстом; читается она и как строка.
- **Ничто не держит узел.** `fio.glob` зовёт системный `glob` прямо
  в потоке событий, `io.open` не уступает вовсе — пакет обходится без
  обоих: каталог читает `fio.listdir` пулом нитей, имена сверяет Lua.
- **Приёмы без ошибок.** Запись со сбросом на диск и проверкой закрытия,
  подмена через временный файл рядом с целью с `O_EXCL` и сбросом
  каталога, снос дерева, не идущий по ссылке, временный каталог, который
  убирается и после броска.
- **Ошибка программиста — исключение, показывающее на вызывающего.**
  Путь не строкой, чужой ключ настроек, права вне `0`…`0777` — бросок
  со строкой того, кто позвал пакет.

## Установка

```sh
tt rocks install tnt-fs --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-fs.git
cd tnt-fs && tt rocks make
```

## Как пользоваться

| Вызов | Что отдаёт |
|---|---|
| `fs.read(path)` | содержимое строкой |
| `fs.write(path, content, opts)` | `true`; пишет с начала, сбрасывает на диск |
| `fs.append(path, content, opts)` | `true`; дописывает в конец, файла нет — заводит |
| `fs.replace(path, content, opts)` | `true`; подменяет файл атомарно |
| `fs.copy(from, to)` | `true`; `to` — каталог: файл ложится в него под своим именем |
| `fs.rename(from, to)` | `true`; в пределах одного тома |
| `fs.remove(path)` | `true`; файл или ссылку — саму ссылку |
| `fs.stat(path)` | `{ kind, size, mode, mtime }`; ссылка раскрывается |
| `fs.exists(path)` | `true` либо `false`; не удалось узнать — пара |
| `fs.list(directory)` | имена по порядку, со скрытыми, без `.` и `..` |
| `fs.glob(directory, mask)` | пути по образцу, по порядку |
| `fs.make_tree(path, opts)` | `true`; уже есть — тоже `true` |
| `fs.remove_tree(path)` | `true`; сносит что угодно по пути, по ссылке не идёт |
| `fs.temp_dir(opts)` | путь нового временного каталога, права `0700` |
| `fs.with_temp_dir(work, opts)` | ответы `work(dir)`; каталог сносится после |
| `fs.MISSING`, `fs.EXISTS`, `fs.DENIED`, `fs.FULL`, `fs.FAILED` | роды отказа |
| `fs.MODE` | права нового файла по умолчанию, `0640` |

Отказ у всех вызовов — пара `nil, err`:

```lua
local _, err = fs.read('/var/lib/app/none.yaml')

err.kind      --> 'missing'
err.errno     --> 2
err.path      --> '/var/lib/app/none.yaml'
tostring(err) --> 'файл /var/lib/app/none.yaml не прочитан: No such file or directory'
```

Права новых файлов — `opts.mode`, девять бит `rwx` (`0`…`0777`);
по умолчанию `0640`, а у `replace` — права старого файла. Образец `glob`
— путь от каталога: `*` — любые знаки, `?` — один, части через косую
черту; квадратных скобок образец не знает и бросает на них.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Проверки идут на настоящем диске, во временном каталоге на каждую;
двойник `fio` берётся только там, где исправный диск отказа не даст.
Покрытие строк — 100 %, убитых мутантов — 100 % (93 проверки, 188 мутантов
в пяти модулях).
