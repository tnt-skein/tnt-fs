# Файловая система

Файлы в Tarantool читают и пишут встроенным `fio` — отдельного рока для
этого не нужно. `tnt-fs` — фасад поверх него: работу делает `fio`, пакет
даёт три вещи, которых у `fio` нет, — один вид отказа, операции, которые
не держат узел, и приёмы, которые иначе пишут руками.

```lua
local fs = require('tnt.fs')

local text, err = fs.read('/var/lib/app/config.yaml')   --> nil, err.kind == fs.MISSING
fs.replace('/var/lib/app/state.json', '{"ok":true}')    --> true, атомарно
fs.glob('/var/lib/app/wal', '*.xlog')                   --> пути по порядку, без блокировки
```

## Зачем пакет

1. **Один вид отказа.** У `fio` их три. Простые действия (`open`, `stat`,
   `rename`, `unlink`, `mkdir`) отдают объект ошибки с полем `errno`.
   Составные, написанные на Lua (`listdir`, `mktree`, `rmtree`,
   `copyfile`), — строку с причиной в конце текста. А глобальный `errno()`
   после составного врёт: `mktree` поверх файла отвечает «File exists»
   при `errno` 2 — это след его же `stat` на предыдущем шаге. Здесь всякий
   отказ — пара `nil, err`, где `err` — таблица с родом, кодом и текстом.
2. **Ничто не держит узел.** `fio` отдаёт работу пулу нитей и ждёт её
   файбером. Но не весь: `fio.glob` зовёт системный `glob` прямо в потоке
   событий, а `io.open`, которым файлы читают по привычке, не уступает
   вовсе. Пакет обходится без обоих — замеры в разделе «Ничто не держит
   узел».
3. **Приёмы, которые иначе пишут руками и с ошибками.** Запись со сбросом
   на диск, подмена файла через временный рядом с целью, снос дерева,
   не идущий по ссылке, временный каталог с уборкой при броске. Написанные
   на месте, они раз за разом выходят с одними и теми же изъянами:
   подмена без сброса на диск и без проверки, что записалось; временный
   файл с постоянным именем, в который два писателя пишут одновременно;
   уборка, которая идёт по ссылке и стирает чужое.

Настроек и состояния у пакета нет. Зависит от `tnt-must` (проверки
аргументов) и `tnt-external` (подмена `fio` в проверках).

## Как пользоваться

```lua
local fs = require('tnt.fs')

local text, err = fs.read('/var/lib/app/config.yaml')
--> nil, файл /var/lib/app/config.yaml не прочитан: No such file or directory

if text == nil and err.kind == fs.MISSING then
    -- файла нет — это «так бывает», а не поломка
end

fs.write('/var/lib/app/config.yaml', 'log_level: info\n')          --> true
fs.replace('/var/lib/app/state.json', json.encode(state))           --> true, атомарно
fs.glob('/var/lib/app/wal', '*.xlog')                                --> пути по порядку

fs.with_temp_dir(function(dir)
    -- черновик: каталог снесётся и после броска
end, { within = '/var/lib/app' })
```

### Что умеет фасад

| Вызов | Что отдаёт |
|---|---|
| `fs.read(path)` | содержимое строкой |
| `fs.write(path, content, opts)` | `true`; пишет с начала, сбрасывает на диск |
| `fs.append(path, content, opts)` | `true`; дописывает в конец, файла нет — заводит |
| `fs.replace(path, content, opts)` | `true`; подменяет файл атомарно |
| `fs.copy(from, to)` | `true`; `to` — каталог: файл ложится в него под своим именем |
| `fs.rename(from, to)` | `true`; в пределах одного тома |
| `fs.remove(path)` | `true`; файл или ссылку — саму ссылку |
| `fs.stat(path)` | `{ kind, size, mode, mtime }`; ссылка раскрывается |
| `fs.exists(path)` | `true` либо `false`; не удалось узнать — пара |
| `fs.list(directory)` | имена по порядку, со скрытыми, без `.` и `..` |
| `fs.glob(directory, mask)` | пути по образцу, по порядку |
| `fs.make_tree(path, opts)` | `true`; уже есть — тоже `true` |
| `fs.remove_tree(path)` | `true`; сносит что угодно по пути, по ссылке не идёт |
| `fs.temp_dir(opts)` | путь нового временного каталога, права `0700` |
| `fs.with_temp_dir(work, opts)` | ответы `work(dir)`; каталог сносится после |
| `fs.MISSING`, `fs.EXISTS`, `fs.DENIED`, `fs.FULL`, `fs.FAILED` | роды отказа |
| `fs.MODE` | права нового файла по умолчанию, `0640` |

Отказ у всех вызовов — пара `nil, err`. Исключение — только ошибка
программиста: путь не строкой, чужой ключ настроек, права вне `0`…`0777`,
квадратные скобки в образце. Бросок показывает на строку вызывающего,
а не внутрь пакета.

## Отказ

`err` — таблица, которая читается и как строка:

```lua
local _, err = fs.read('/var/lib/app/none.yaml')

err.kind      --> 'missing'
err.errno     --> 2
err.path      --> '/var/lib/app/none.yaml'
err.message   --> 'файл /var/lib/app/none.yaml не прочитан: No such file or directory'

'причина: ' .. err           --> причина: файл /var/lib/app/none.yaml не прочитан: No such file or directory
json.encode({ err = err })   --> {"err":"файл /var/lib/app/none.yaml не прочитан: No such file or directory"}
```

Главное поле — род. Решать надо по нему, а не по тексту: текст причины
даёт система, и на другой системе он другой.

| Род | Когда | Коды |
|---|---|---|
| `missing` | по пути ничего нет, либо часть пути — файл, а не каталог | `ENOENT`, `ENOTDIR` |
| `exists` | место занято: файл уже есть, каталог не пуст | `EEXIST`, `ENOTEMPTY` |
| `denied` | нет прав либо файловая система только для чтения | `EACCES`, `EPERM`, `EROFS` |
| `full` | кончилось место или квота | `ENOSPC`, `EDQUOT` |
| `failed` | всё прочее: ввод-вывод, перенос между томами, каталог там, где нужен файл | остальные |

Код остаётся в `err.errno`, если он был, — тому, кому рода мало. У строки
составного действия код узнаётся по причине **в конце** текста: путь
в начале волен называться словами причины. Причина в `message` — словами
системы, без приставки `fio:` и без путей, которые составные действия
вписывают в текст сами. Отказ без причины (`fio` на 3.8 такого не даёт)
— `failed` с текстом «причина неизвестна», а не исключение.

## Чтение и запись

`read` читает файл целиком; `write` пишет с начала, `append` — в конец.
Записанное сбрасывается на диск (`fsync`) до закрытия: строка, оставшаяся
в кэше страниц, переживает закрытие файла и не переживает отключения
питания. Закрытие проверяется тоже — сетевая файловая система сообщает
об отказе записи именно на нём. Файл закрывается при всяком исходе,
а сброс после неудавшейся записи не зовётся: его успех выдал бы отказ
за удачу.

```lua
fs.append('/var/lib/app/audit.log', 'first\n')    --> true
fs.append('/var/lib/app/audit.log', 'second\n')   --> true
fs.read('/var/lib/app/audit.log')                 --> 'first\nsecond\n'
```

Права нового файла по умолчанию — `0640` (`fs.MODE`): владельцу чтение
и запись, группе чтение, прочим ничего. В файлы, которые пишет узел,
попадают его данные, и «как получится» означало бы umask того, кто
запустил процесс; группа читает намеренно — выгрузки разбирает агент под
своей учётной записью. Свои права — `opts.mode`, девять бит `rwx`
(`0`…`0777`); umask процесса, как всегда у `open`, их урезает:

```lua
fs.write('/var/lib/app/token', 'secret', { mode = tonumber('600', 8) })   --> true, права 600

fs.write('/var/lib/app/token', 'secret', { mode = 644 })
--> бросок: настройки.mode — число от 0 до 511, а не 644
```

Второй вызов — частая ошибка: `644` в Lua десятичное, это `0o1204`, и файл
получил бы бит `sticky` без чтения владельцу. Граница `0777` её ловит.

**`write` и `append` не атомарны.** Отказ посреди записи оставляет
обрезанный файл: `write` открывает его с `O_TRUNC`. Файл, который читают,
пока его пишут, — настройки, состояние, снимок — подменяют `replace`.

## Подмена файла: `replace`

Читающий видит либо старое содержимое, либо новое — никогда половину:

1. новое пишется во временный файл **рядом с целью** —
   `.<имя>.<16 шестнадцатеричных знаков>.tmp`, открытый с `O_EXCL`:
   чужой файл с тем же именем пакет не откроет, а случайная часть не даст
   двум писателям одного файла столкнуться;
2. временный файл сбрасывается на диск и закрывается;
3. `rename` кладёт его поверх цели;
4. сбрасывается сам каталог: переименование — запись в каталоге, и без
   этого после отключения питания на месте может оказаться старый файл.

Рядом с целью, а не в `/tmp`: переименование атомарно только в пределах
одной файловой системы, а `/tmp` на боевой машине обычно tmpfs, и `rename`
оттуда отвечает `EXDEV` — «Invalid cross-device link» (проверено на 3.8
под Linux; на macOS тот же код пишется «Cross-device link»).

```lua
fs.replace('/var/lib/app/token', 'новый')    --> true
fs.list('/var/lib/app')                      --> { 'audit.log', 'config.yaml', 'state.json', 'token', 'wal' }

fs.replace('/var/lib/app/missing/state.json', '{}')
--> nil, файл /var/lib/app/missing/state.json не заменён: No such file or directory
```

Временного файла в списке нет: он либо переименован на место, либо
убран. Права без `opts.mode` берутся **у старого файла**: подмена
не должна молча открыть файл с тайнами шире, чем он был (`token`
с правами `0600` остаётся `0600`). Нового файла — `fs.MODE`. При отказе
до переименования временный файл убирается, старый остаётся нетронутым.
Отказ сброса каталога называется своим текстом — «каталог … не сброшен
на диск» — и приходит, когда файл **уже на месте**: не сброшен только
каталог.

## Каталоги

```lua
fs.make_tree('/var/lib/app/data/512/0', { mode = tonumber('750', 8) })   --> true
fs.stat('/var/lib/app/data')     --> { kind = 'directory', mode = 488, size = 96, mtime = 1789772606 }
fs.exists('/var/lib/app/data')   --> true
fs.exists('/var/lib/app/nope')   --> false

fs.make_tree('/var/lib/app/token/x')
--> nil, каталог /var/lib/app/token/x не создан: File exists   (err.kind == 'exists')
```

`stat` раскрывает ссылку и отдаёт простую таблицу: `kind` — `file`,
`directory` либо `other` (устройство, сокет, канал), `mode` — права
(младшие двенадцать бит, `488` — это `0750`), `mtime` — целые секунды
на любой системе: дробь, которую `fio` отдаёт на Linux, отбрасывается вниз.
`exists` различает «нет» (`false`, в том числе у ссылки в никуда, как
`fio.path.exists`) и «не удалось узнать» — пара с родом `denied` или иным.

`remove_tree` сносит то, что лежит по пути, целиком: каталог — со всем
содержимым, файл и ссылку — их самих. **По ссылке он не идёт**, и это
не мелочь: `fio.rmtree` по ссылке на каталог вычищает каталог, на который
она указывает, и только потом отказывает на самой ссылке «Not a directory»
(проверено на 3.8). Уборка временной ссылки стирала бы чужие данные.

```lua
-- /var/lib/app/alias → /var/lib/app/data
fs.remove_tree('/var/lib/app/alias')       --> true: снята ссылка
fs.exists('/var/lib/app/data/512/0')       --> true: данные на месте

fs.remove_tree('/var/lib/app/data')        --> true
fs.remove_tree('/var/lib/app/data')
--> nil, /var/lib/app/data не снесён: No such file or directory   (err.kind == 'missing')
```

Уборка, которой нечего убирать, — отказ `missing`, а не удача: вызывающий
отличит его сам (`err.kind == fs.MISSING`), а «снёс» и «сносить было
нечего» — разные ответы.

## Поиск по образцу: `glob`

```lua
fs.glob('/var/lib/app/wal', '*.xlog')
--> { '/var/lib/app/wal/00000000000000000001.xlog',
-->   '/var/lib/app/wal/00000000000000000002.xlog' }

-- данные vinyl — двумя уровнями ниже: каталог спейса, каталог индекса
fs.glob('/var/lib/app/vinyl', table.concat({ '*', '*', '*.run' }, '/'))
--> { '/var/lib/app/vinyl/512/0/00000000000000000005.run',
-->   '/var/lib/app/vinyl/513/0/00000000000000000007.run' }

fs.glob('/var/lib/app/wal', '*.none')      --> {}
fs.glob('/var/lib/app/nowhere', '*.xlog')
--> nil, каталог /var/lib/app/nowhere не прочитан: No such file or directory
```

Образец вложенных файлов во втором примере склеен из частей нарочно:
пара «косая черта со звёздочкой» в исходнике на Lua слепит генератор
мутантов — он читает её как начало комментария C и перестаёт видеть
остаток файла. В документе её можно писать и целиком.

Правила образца:

- образец — путь **от каталога**: части через косую черту, начинается
  не с неё;
- в части `*` — любые знаки, `?` — один знак, остальное — само себя,
  в том числе `.`, `-`, `+`, `%` и кириллица;
- промежуточные части подходят только каталогам: файл на пути пропускается,
  ссылка на каталог раскрывается, как у системного `glob`;
- скрытые имена (с точки) подходят только к части, которая сама
  начинается с точки: `*` не захватит временный файл подмены `.state.json.….tmp`;
- **квадратных скобок образец не знает**, и они — ошибка программиста:
  у `fio.glob` это набор знаков, и молча прочитанные буквально, они нашли
  бы не то, что искали;
- каталога поиска нет — отказ `missing`: «нечего искать» и «ничего
  не нашлось» (`{}`) — разные ответы. `fio.glob` в обоих случаях отдаёт
  пустой список;
- каталог, пропавший по дороге, пропускается; недоступный — отказ всего
  поиска: список, в котором молча нет недоступного каталога, выдал бы
  неполное за полное.

```lua
fs.glob('/var/lib/app', '[0-9]*.xlog')
--> бросок: образец — строка по образцу ^[^/%[%]][^%[%]]*$, а не «[0-9]*.xlog»
```

## Временные каталоги

Где заводить временный каталог, решает то, что из него потом сделают.

| Вызов | Где | Когда |
|---|---|---|
| `fs.temp_dir()` | системный: `$TMPDIR`, иначе `/tmp` (`fio.tempdir`) | черновик, который выбросят |
| `fs.temp_dir({ within = dir })` | `dir/.tmp-<16 знаков>` | то, что потом переименуют на место |

```lua
fs.temp_dir()                              --> '/tmp/jPn0xY', права 700
fs.temp_dir({ within = '/var/lib/app' })   --> '/var/lib/app/.tmp-a5e7d36d79b68cbb', права 700
```

Имя в `within` скрытое: образец `*` у соседей его не захватит, и уборщик,
чистящий каталог по образцу, не снесёт чужую работу на ходу. Случайная
часть — восемь байтов `digest.urandom`: имя не угадать заранее
и не подсунуть на его место свой каталог.

`temp_dir` каталог только заводит — убирает его вызывающий.
`with_temp_dir` убирает сам, при всяком исходе:

```lua
fs.with_temp_dir(function(dir)
    fs.write(dir .. '/part-1', 'данные')

    return fs.rename(dir .. '/part-1', '/var/lib/app/export.csv')
end, { within = '/var/lib/app' })
--> true; каталога .tmp-… больше нет

fs.with_temp_dir(function(dir)
    error('сломалось на полпути', 0)
end, { within = '/var/lib/app' })
--> бросок: сломалось на полпути; каталога .tmp-… тоже нет
```

- ответы работы возвращаются как есть, все, со всеми `nil` посередине;
  пара `nil, err` самой работы проходит насквозь;
- бросок работы уходит дальше **тем же значением** — таблица остаётся той
  же таблицей, строка — без приписанного места, — а каталог перед этим
  сносится;
- работа вернулась, а каталог не снёсся — пара `nil, err`: оставленный
  черновик с чужими данными — отказ, о котором вызывающий обязан знать;
- каталог не завёлся — пара `nil, err`, и работа не зовётся вовсе.

## Ничто не держит узел

Сосед — файбер, который считает, сколько раз получил управление. Ноль
тиков за действие значит, что узел на это время стоял целиком: ни запросов,
ни репликации, ни проб живости. Замер на 3.8, macOS, 20 000 файлов
в каталоге и файл в 200 МБ:

| Действие | Время | Тиков соседа |
|---|---|---|
| `fio.glob` по 20 000 файлам | 56 мс | **0** |
| `fio.listdir` по тем же файлам | 11 мс | 5 671 |
| `io.open` и чтение 200 МБ | 43 мс | **0** |
| `fio` — чтение тех же 200 МБ | 29 мс | 16 918 |
| `io` — запись 200 МБ | 45 мс | **0** |
| `fio` — запись 200 МБ со сбросом | 39 мс | 25 262 |
| `fio.copyfile` 200 МБ | 120 мс | 119 099 |
| `fio.rmtree` 20 000 файлов | 860 мс | 779 008 |

На здоровом диске разница — десятки миллисекунд. На подмороженной сетевой
файловой системе системный `glob` и `io.read` не отвечают вовсе, и узел
стоит, пока не ответят; `fio` в том же положении занимает нить пула,
а файбер ждёт, не мешая соседям. Поэтому `glob` здесь — `fio.listdir`
и сверка имён в Lua, а `io` в пакете нет. Проверки закрепляют это: сосед
обязан тикнуть за каждое из `write`, `read`, `replace`, `remove` и `glob`.

## Проверки

Проверки лежат в `test/` и идут на **настоящем диске**, в своём
временном каталоге на каждую проверку, с маской прав `022`: пакет —
тонкий слой над `fio`, и двойник диска проверял бы только то, что мы
правильно разговариваем сами с собой.

Двойник берётся там, где исправный диск отказа не даст: кончилось место,
не сбросился файл, не закрылся, не открылся каталог. Внешняя зависимость
у пакета одна — `fio` целиком и случайная часть имён, — и подменить в ней
довольно одно действие, остальное берётся у настоящего:

```lua
fs._set_source({
    fio = setmetatable({
        rename = function()
            return false, { errno = errno.EXDEV }
        end,
    }, { __index = fio }),
})

fs.replace('/var/lib/app/state.json', '{}')
--> nil, файл /var/lib/app/state.json не заменён: Invalid cross-device link
--  (текст — strerror машины: на macOS «Cross-device link»)
```

## Чем пришлось поступиться

- **`write` и `append` не атомарны** — см. «Чтение и запись». Атомарна
  только `replace`, и она дороже: временный файл, два сброса
  и переименование.
- **Сброс на диск на каждой записи и без выключателя.** `append` в журнал
  по строке платит `fsync` за каждую строку. Выключателя нет намеренно:
  запись, которую теряет отключение питания, должна быть видна в коде
  вызывающего, а не пропадать в настройке.
- **`replace` меняет ссылку на файл.** Цель-ссылка после подмены — обычный
  файл, а то, на что она указывала, не тронуто. Права берутся у старого
  файла, но владелец и группа — у процесса, и umask их урезает: файл
  `0666` после подмены под umask `022` — `0644`.
- **Весь файл — в памяти.** `read` и `write` берут содержимое целиком;
  потокового чтения и записи в пакете нет. Журналы и снимки в сотни
  мегабайт читают потоком — курсором `xlog`, — а не этим пакетом.
- **`glob` беднее системного**: ни квадратных скобок, ни `\` для
  экранирования, ни частей `.` и `..` — `fio.listdir` их не перечисляет,
  и такая часть не находит ничего. Сам `fio.listdir` разбирает список
  имён в Lua без уступки: каталог в миллион имён держит узел на время
  этого разбора так же, как у самого `fio`.
- **Род отказа `remove` на каталоге зависит от системы**: `unlink`
  каталога на macOS — `EPERM` (`denied`), на Linux — `EISDIR` (`failed`).
  Каталог сносят `remove_tree`.
- **Бросок работы важнее уборки.** Работа `with_temp_dir` бросила, а
  каталог не снёсся — уходит бросок, и каталог остаётся без слова о нём:
  второго канала, кроме журнала, у пакета нет, а журнала он не пишет.
- **`copy` в каталог кладёт файл под его именем** — так делает
  `fio.copyfile`, и пакет этого не меняет.
